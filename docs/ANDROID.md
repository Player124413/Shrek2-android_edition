# Android

Порт для телефонов и планшетов на Android 7.0+ с 64-битным процессором ARM (arm64-v8a) и OpenGL ES 3.0. APK —
это лаунчер (настройки, папка игры, редактор управления) и сама игра (`libmain.so` из того же кода, что и на
Switch, поверх SDL2). **Статус: APK собирается в GitHub Actions (`.github/workflows/android.yml`, без игры); запуск на телефоне и
производительность не проверены [проверить].**

Как и для Switch, APK собирается **из своей копии игры**: в него входит C, сгенерированный из её DLL. Готовые
игровые APK не распространяются.

## Сборка

Нужно:

* сгенерированные модули: `build/gen` (английская) или `build/gen-rus` (русская) — [BUILDING.md](BUILDING.md),
  «Подготовка своей игры» и «Русская версия». Генерировать можно на маке или в Linux;
* JDK 17, Android SDK (`ANDROID_HOME`) с пакетами `platforms;android-35`, `ndk;27.2.12479018`, `cmake;3.31.6`:

```sh
sdkmanager "platforms;android-35" "build-tools;35.0.0" "ndk;27.2.12479018" "cmake;3.31.6"
```

Дальше, из корня репозитория:

```sh
tools/android_deps.sh --ffmpeg   # SDL2, openal-soft, ogg/vorbis, FreeType, FFmpeg (декодер Bink) -> build/android-deps
tools/build.sh android           # -> build/shrekNX-eng.apk
tools/build.sh android-rus       # -> build/shrekNX-rus.apk (ставится рядом с английской)
```

`--ffmpeg` можно не указывать: тогда ролики идут чёрным кадром со звуком. `tools/build.sh android` сам скачивает
Gradle (файла `gradle-wrapper.jar` в репозитории нет), если `gradle` не установлен. Сборка сгенерированного кода
долгая (как и для Switch): десятки минут.

Подпись: без настроек release-APK подписывается отладочным ключом. Свой ключ — файл `android/keystore.properties`
(в git не попадает):

```properties
storeFile=release.jks
storePassword=...
keyAlias=shrek
keyPassword=...
```

## Сборка в GitHub Actions

Workflow `.github/workflows/android.yml` запускается при изменениях кода порта (и вручную, «Run workflow»):
ставит NDK и CMake, собирает библиотеки (кэшируются), APK и проверяет его (`libmain.so`, `libSDL2.so`, функции
JNI, выравнивание 16 КБ, подпись). Ошибки сборки и сводка по APK выводятся аннотациями.

* **Без файлов игры** (публичный репозиторий) получается артефакт `shrekNX-android-nogame`: весь код порта,
  лаунчер и редактор управления, но без кода игры (`SNX_NO_GAME`) — «Играть» показывает сообщение. Он годится,
  чтобы проверить сборку, лаунчер и экранное управление на телефоне.
* **С игрой** — вкладка Actions → «Android APK» → **Run workflow** и поля:
  * **ссылка на архив игры** — zip, 7z или rar с папкой установленной игры (или только `System`); ссылка прямая
    или публичная Яндекс Диска, Google Диска, Dropbox. Из архива берутся только 12 модулей `System` (`Core.dll`,
    `Engine.dll`…, `game.exe`), регистр имён не важен. **`game.exe` должен быть распакованным** (без SafeDisc,
    как для мака и Switch) — защищённый workflow распознаёт и останавливается;
  * **версия** — `eng` или `rus` (для русской в `System` должен лежать распакованный английский `game.exe`, как
    после `tools/make_rus.sh`);
  Получается артефакт `Shrek2-<версия>-<номер>.apk` — сам APK, без zip (хранится 7 дней). **Внимание:**
  артефакты публичного репозитория может скачать любой вошедший на GitHub — APK с кодом игры лучше собирать в
  приватном репозитории или удалять артефакт после скачивания.

  Ссылка скрывается в логах (`::add-mask::`), но поля запуска видны тем, у кого есть доступ к
  репозиторию: давайте временную ссылку и удалите файл после сборки. Вместо поля можно задать секрет
  репозитория `SNX_GAME_SYSTEM_URL` (используется, если поле пустое). APK должен совпадать с данными игры на
  телефоне — берите одну и ту же копию. Генерация и сборка кода игры в CI занимают десятки минут (лимит —
  5 часов). [проверить: путь с настоящей игрой в CI не запускался]
* Скачать архив игры и достать `System` можно и локально: `tools/fetch_game.sh <ссылка> game/System`.

## Обновления и подпись

Все сборки (локальные и из CI) подписываются одним ключом `android/shreknx-release.jks.b64`, а `versionCode` —
минуты от 2026-01-01 до последнего коммита (в имени APK — `0.1.0-<число коммитов>`): **новая версия ставится
поверх старой, настройки, раскладка и сохранения остаются.**
APK, собранные до появления ключа (подписанные случайным отладочным ключом), один раз придётся удалить.

«Приложение не установлено» при обновлении — обычно одно из трёх: установлен APK с тем же пакетом, но другим
ключом (старая сборка до ключа; пакет без игры и английская версия — `com.shreknx.game`, русская —
`com.shreknx.game.rus`), установлена версия новее (`versionCode` больше), или мало места в памяти телефона.

Ключ и его пароль (`shreknx-android`) лежат в открытом репозитории — подписать им «обновление» может кто угодно.
Для своих публичных сборок замените его: свой `android/keystore.properties` (см. выше) или секреты CI
(`SNX_KEYSTORE` — путь к файлу, `SNX_KEYSTORE_PASSWORD`, `SNX_KEY_ALIAS`, `SNX_KEY_PASSWORD`); проверку отпечатка
ключа в `.github/workflows/android.yml` тогда тоже поменяйте. Смена ключа — снова одно удаление старой версии.

## Установка и первый запуск

1. `adb install -r build/shrekNX-eng.apk` (или скопировать APK на телефон).
2. Файлы игры — папка установленной игры с ПК (`System`, `Maps`, `Textures`, `Sounds`, `Music`…), **та же копия**,
   из которой генерировался код (иначе ошибка CRC модуля). Два способа:
   * **по USB** — скопировать в `Android/data/com.shreknx.game/files/game/` (русская —
     `com.shreknx.game.rus`). Разрешения не нужны, это папка по умолчанию;
   * **«Импорт из папки…»** в лаунчере — выбрать папку системным диалогом, файлы скопируются туда же.

   Разрешений на файлы у приложения нет (только вибрация): чтение игры из любой папки с «Доступом ко всем
   файлам» убрано — Play Protect предупреждал о «возможно опасном приложении».
3. «Играть». Лог порта — `Android/data/<пакет>/files/user/snx.log` (кнопка «Журнал» в лаунчере), лог движка —
   `user/System/game.log`, настройки и сохранения — `user/`. **Сохранения удаляются вместе с приложением.**

## Управление

Экранное управление рисует лаунчер поверх игры (`android/…/TouchControlsView.kt`) и передаёт игре как виртуальный
геймпад, поэтому раскладка кнопок та же, что на Switch ([CONSOLE.md](CONSOLE.md)): A — удар, B — прыжок,
«Меню» — Plus, «Зелья» — ZL (с ним A/B — зелья).

* **Слот зелья.** Слева и справа от «Зелий» — стрелки ◀ ▶, снизу справа — номер слота (1–9, по кругу;
  запоминается). Короткое нажатие «Зелий» — клавиша цифры слота (как 1–9 на ПК): выпить зелье этого слота.
  Если, держа «Зелья», нажать другую кнопку или крестовину, — это прежний слой ZL (ZL+«Удар» — 6, ZL+«Прыжок» —
  7), и слот не пьётся. С залипанием (toggle) «Зелья» — только слой ZL. Какое зелье в каком слоте — решает
  игра. (`TouchControlsView.kt`, `drawSlot`/`drinkSlot`; `Settings.potionSlot`.) [проверить на устройстве]

* **Левый стик** — ходьба; стоит на месте (не ездит под пальцем). В редакторе можно включить «Плавающий» —
  тогда он появляется там, где коснулся левой части экрана, и тоже не сдвигается при движении пальца.
  Направление ближе 25° к оси прилипает к ней: «влево/вправо» — строго вбок (перебирание руками на карнизе не
  срывается вверх или вниз), «вперёд» — строго вперёд; между осями — диагональ.
* **Палец на свободном месте** — камера (как мышь на ПК; чувствительность — в лаунчере).
* Кнопки «скользят»: можно переводить палец с одной на другую, не отрывая.
* Вид — «в стиле Шрека»: болотные кнопки с ушами-трубочками огра и кремовыми значками (удар — кулак, прыжок —
  стрелка, зелья — колба, меню, центр камеры, Esc, Ввод), головка стика — голова Шрека. Значки — SVG-пути
  (`ShrekIcons.kt`, разбор — `SvgPath.kt`: Android сам SVG не читает); у кнопок без значка (ZR, зелья 1–9) — надпись.
* В меню игры экранные кнопки прячутся: касание — щелчок по пункту меню. «Назад» телефона — выход из игры
  с подтверждением (меню игры — кнопка «Меню»). Кнопок L/R, «Камера» (Y) и «Действие» (X) на экране нет.
* Подключён геймпад (Bluetooth/USB) — экранные кнопки прячутся сами (отключается в лаунчере).

**Редактор раскладки** — в лаунчере («Редактор раскладки») или в игре (шестерёнка в левом верхнем углу; игра идёт
дальше). Перетаскивание — переместить, двумя пальцами — размер; на панели — размер, непрозрачность, «Показывать»,
«Плавающий» для стиков, «Залипание» для кнопок, общая прозрачность. Скрытые по умолчанию элементы (крестовина,
правый стик, ZR, Minus, «Центр», Esc, «Ввод», зелья 1–9 цифрами) включаются через «Показать скрытые элементы…».
Раскладка хранится в `files/touch_layout.json` в долях экрана — подходит к любому разрешению.

## Скорость

Лаунчер сам выбирает пресет по памяти и частоте процессора (`Device.tier`): «Слабый» (50 % разрешения, 30 FPS,
16-битные текстуры, кэш файлов 96 МБ), «Средний» (75 %, 60 FPS, 256 МБ), «Мощный» (100 %, 60 FPS, 512 МБ).
Всё меняется вручную. Что делает порт:

| Приём | Где |
|---|---|
| Главный поток гостя и поток рендера — на «больших» ядрах (по `cpuinfo_max_freq`), приоритет выше обычного, подсказки производительности ADPF (Android 12+) с длительностью кадра | `platform/android/thread.c`, `frame_pace` в `d3d8_ff.c` |
| Собранные программы GL кешируются на диск (`glProgramBinary`): фризы от сборки шейдеров — только в первый раз | `platform/gles_shim.c`, `link_body` |
| Разрешение рендера — доля экрана (`SNX_RENDER_SCALE`), кадр растягивается при показе | `host/boot/main.c`, `boot_render_size` (`config.c`) |
| Ограничение FPS (`SNX_FPS_CAP`) — меньше нагрев и троттлинг | `frame_pace` |
| Экран 90/120 Гц переключается на частоту, равную ограничению (`preferredDisplayModeId`, `Surface.setFrameRate`): кадры отмеряет vsync, а не сон ограничителя — без рывков 8/17/25 мс. В `snx.log` — `display 60.0 Hz, FPS cap 60: vsync pacing` | `GameActivity.pickDisplayMode`, `plat_set_display` (`platform/window.c`) |
| DXT без `GL_EXT_texture_compression_s3tc` распаковывается на ЦП; `SNX_TEX16=1` — в 16 бит (вдвое меньше памяти) | `gles_shim.c` |
| Стабильная производительность (`setSustainedPerformanceMode`), Game Mode, `preferMinimalPostProcessing` | `GameActivity.kt`, манифест |
| Сворачивание: поток рендера отпускает контекст и ждёт, звук OpenAL на паузе | `platform/window.c`, `openal.c` |

## Широкие экраны (20:9, 21:9)

* Кадр — во весь экран, включая вырез камеры (`windowLayoutInDisplayCutoutMode=shortEdges`), без полей от системы
  на старых прошивках (`android.max_aspect`, `maxAspectRatio` = 3,0 в манифесте).
* 3D — Hor+ для любых пропорций (`ovr_engine_camera_matrices`, `runtime/overrides_engine.c`): вертикальный угол
  как в 4:3, по бокам видно больше. Горизонтальный угол: 90° игры → ≈106° на 16:9, ≈120° на 21:9.
* Список режимов экрана D3D8 (`d3d8.c`, `mode_list`) включает размер кадра порта: полноэкранный рендер игры
  берёт ближайший к `FullscreenViewportX/Y` режим из списка, и без этого кадр на 20:9 становился 16:9
  (1280x720 / 1920x1080) с чёрными полосами даже в «Весь экран». В `snx.log` — `[d3d8] display modes: + screen
  WxH` и `[d3d8] back buffer WxH` (должен совпасть с `[boot] render`). [проверить на устройстве]
* 2D-интерфейс и меню игры растягиваются по ширине (движок рассчитан на 4:3). Лаунчер, «Формат кадра»:
  «Весь экран» (по умолчанию), «16:9» или «4:3» — кадр сужается до этих пропорций, по бокам чёрные поля
  (`SNX_ASPECT`, `boot_render_size`: тест — `tests/rt/ini_test.c`, раздел 6). Касания в меню пересчитываются с
  учётом полей (`d3d8_window_to_target`), ролики вписываются в кадр. В `snx.log` — строка
  `[boot] render WxH (scale …, aspect …)`. [проверить на устройстве: интерфейс в 4:3 без растяжения]

## Отличия от GL 4.1 (прослойка ES)

`platform/gles_shim.h` подменяет вызовы, которых нет в OpenGL ES 3.0: форматы D3D8 (BGRA, BGR, 1555/4444)
перекладываются на ЦП, `glGetTexImage`/`glReadPixels` в другие форматы — через временный FBO, D32 → D24,
`glDrawElementsBaseVertex` — из ES 3.2/расширения или сдвигом указателей атрибутов, цвет вершин D3DCOLOR
переставляет шейдер, плоскости отсечения без `GL_EXT_clip_cull_distance` — `discard` в шейдере. Не поддерживаются
(с предупреждением в логе): каркасный режим, цвет края текстур без `GL_EXT_texture_border_clamp`, смещение LOD
в сэмплере, чтение сжатых текстур и глубины [проверить: заметно ли это в игре].

## Переменные

Задаются в лаунчере («Дополнительно» → «Переменные SNX_*»), по строке `ИМЯ=ЗНАЧЕНИЕ`; кроме общих
([AGENTS.md](../AGENTS.md), «Переменные запуска»):

| Переменная | Назначение |
|---|---|
| `SNX_RENDER_SCALE=0.75` | разрешение рендера (доля экрана, 0,25–1) |
| `SNX_ASPECT=16:9`, `4:3` | предел пропорций кадра (лаунчер: «Формат кадра»); без него — во весь экран |
| `SNX_FPS_CAP=30` | ограничение кадров в секунду |
| `SNX_TEX16=1` | DXT, распакованные на ЦП, — в 16 бит |
| `SNX_GLES_S3TC=0` | распаковывать DXT на ЦП и при наличии расширения (проверка) |
| `SNX_SHADER_CACHE=<папка>`, `=0` | кэш программ GL; `0` — без кэша |
| `SNX_AFFINITY=0`, `SNX_ADPF=0` | не закреплять потоки за большими ядрами; без подсказок ADPF |
| `SNX_SHOW_FPS=1` | счётчик кадров (поверх `Snx.ini`) |

## Частые проблемы

| Симптом | Проверка |
|---|---|
| «Игра не найдена» | в выбранной папке должны быть `System/Core.u`, `System/Engine.u` и `Maps` |
| Вылет сразу после запуска, в логе CRC | APK и файлы игры — из разных копий; перегенерируйте код и пересоберите |
| Нет доступа к папке | «Импорт из папки…» или копирование по USB в папку по умолчанию |
| Play Protect: «приложение может быть опасным» | APK не из Google Play и мало кому известен: «Подробнее» → «Всё равно установить» или отправить на проверку |
| Мало FPS / нагрев | пресет «Слабый», ограничение 30 FPS, «Стабильная производительность» |
| Рывки при 60 FPS | ограничение 60 (не «Нет»); в `snx.log` — `vsync pacing`; редкие долгие кадры — строки `[hitch]` (сборка шейдеров, чтение с диска, заливка текстур) |
| Чёрные ролики | APK собран без FFmpeg: `tools/android_deps.sh --ffmpeg` и пересборка |
